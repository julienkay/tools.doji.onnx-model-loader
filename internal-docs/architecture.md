# Architecture

## Assemblies

| Assembly | Contents |
|---|---|
| `Unity.InferenceEngine` (via asmref) | `Runtime/InferenceEngine`: converter, loader, metadata reader, internal parser copies |
| `Doji.AI.ONNXModelLoader.Editor.Tests` | EditMode tests in `Tests/Editor` |

`Runtime/InferenceEngine` holds an assembly definition reference to Sentis'
`Unity.InferenceEngine`. Its code compiles into the Sentis assembly, so the
converter can use Sentis internals such as `ModelConverterBase` layers and
`Model` construction.

`ONNXNodeWrapper.cs` adds `InternalsVisibleTo` for the test assembly, so tests
can use the internal converter types and parser copies.

The companion project references the package with `file:` and lists it in
`testables`.

## Parser copies

The package depends on `tools.doji.formats.onnx`, and users get its public
`Doji.ONNX` types and `OnnxModelSignatureReader` from there. The converter
cannot use them: `Unity.InferenceEngine` is a Sentis assembly and an asmref
cannot add references to it. So `Runtime/InferenceEngine/Onnx` holds two
internal copies:

| Copy | Made from |
|---|---|
| `Onnx.cs` | `onnx.proto3`, regenerated by `protoc-gen-unity` with `visibility=internal` |
| `ProtoReader.cs` | `ProtoReader.cs`, with its top-level classes made internal |

Both are internal, so assemblies that reference `Unity.InferenceEngine` and
`Doji.Onnx` (for example hf-hub's Editor assembly) see only one `Doji.ONNX`
type set.

`tools/sync-onnx-parser/sync.sh [--check] [path]` writes the copies from a
`tools.doji.formats.onnx` checkout (default: the sibling folder). It needs
`protoc` and the .NET 8 SDK. Each copy's header records the SHA-256 of its
source file, without carriage returns. `OnnxParserCopyTests` fails when a copy
is out of date or a copied type is public.

## Conversion

`OnnxModelLoader.Load(path)` runs `ONNXModelConverter.Convert(path)` and
returns a Sentis `Model`. The converter follows the Sentis ONNX importer:
`ONNXNodeWrapper` adapts nodes, `ONNXConstantsLoader` reads initializers,
`ModelConverterBase` builds layers.

## Streaming readers

Some callers need model data before a full conversion.
`ModelProto.Deserialize` would materialize nodes, initializers and raw tensor
payloads, so these readers scan only the fields they need and seek past the
rest.

- `OnnxModelLoader.LoadMetadata(path)` returns `ONNXModelMetadata` from the
  top-level `ModelProto` fields. It seeks past graph, opset, training,
  function, and configuration payloads with `ProtoReader.SkipField`.
- Graph inputs come from `OnnxModelSignatureReader` in
  `tools.doji.formats.onnx`.

The reader uses the bounded `ProtoReader` API: every length is checked
against the end of its message, and skipped payloads are never read. Memory
depends on the returned data, not on the file size.

## Package boundary

Generated schema types (`Doji.ONNX`), `ProtoReader`, and the generator
belong to `tools.doji.formats.onnx`. Make shared protobuf helpers and
generator changes there first. Loader-specific parsing policy and Sentis
conversion stay here.

## Tests

Tests build protobuf bytes in memory with `ProtoWriter` and do not use Editor
ONNX import APIs.

| File | Covers |
|---|---|
| `ONNXModelLoaderTests.cs` | Conversion of the models in `Tests/Editor/Models`, a Conv with `pads` run on the CPU, metadata reads that skip the graph |
| `ONNXNodeWrapperTests.cs` | INTS, FLOATS, and STRINGS attributes parsed from wire bytes |
| `OnnxParserCopyTests.cs` | Parser copies match `tools.doji.formats.onnx` and stay internal |

## Known limits

- The parser copies must be re-synced after every change to
  `tools.doji.formats.onnx`; `OnnxParserCopyTests` catches a stale copy.
- The converter classes are in namespace `Unity.InferenceEngine`, and the
  code compiles into a Sentis assembly. The Asset Store guidelines forbid code
  in Unity namespaces (2.5.a), so the package is published outside Asset Store
  review.
- `ONNXNodeWrapper.GetOptionalFloatArray` looks for attribute type `FLOAT`
  instead of `FLOATS`, as the Sentis importer does. Only LSTM
  `activation_alpha` and `activation_beta` use it.
- The converter depends on Sentis internals through the asmref. A Sentis
  upgrade can break it. No supported Sentis version range is declared beyond
  the `2.6.1` dependency.
- The sample asmdef is named `Doji.Temp_delete_useReference instead.Samples`.
- The companion project still uses Unity 6000.3.10f1.
